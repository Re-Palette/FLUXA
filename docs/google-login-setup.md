# Google ログインの設定手順

FLUXA の「Google でログイン」と、Google ドライブ・スプレッドシート・Gmail・カレンダーの連携は、同じ **Google OAuth クライアント**を使います。設定は一度だけです。

所要時間: 約 10 分。必要なもの: Google アカウント（Google Cloud を利用できるもの）

---

## 1. Google Cloud プロジェクトを用意する

1. <https://console.cloud.google.com/> を開く
2. 画面上部のプロジェクト選択 →「新しいプロジェクト」→ 名前（例: `fluxa`）を入れて作成
3. 作成したプロジェクトが選択されていることを確認

## 2. OAuth 同意画面（Google Auth Platform）を設定する

1. 左メニュー「API とサービス」→「OAuth 同意画面」（または <https://console.cloud.google.com/auth/overview>）→「開始」
2. **アプリ情報**: アプリ名 `FLUXA`、ユーザーサポートメールを選択
3. **対象**: 「外部」を選択（Google Workspace の社内だけで使う場合は「内部」）
4. **連絡先情報**: 自分のメールアドレス
5. 作成

### テストユーザーを追加する（「外部」を選んだ場合）

公開前のアプリは「テスト」状態で、**登録したテストユーザーしかログインできません**。

- 「対象」→「テストユーザー」→「ユーザーを追加」で、ログインに使う Google アカウントを追加

## 3. OAuth クライアントを作成する

1. 「クライアント」→「クライアントを作成」
2. アプリケーションの種類: **ウェブ アプリケーション**
3. 名前: `FLUXA Web`（任意）
4. **承認済みの JavaScript 生成元**:

   ```
   http://localhost:3000
   ```

5. **承認済みのリダイレクト URI**（2つとも追加。1文字でも違うとエラーになります）:

   ```
   http://localhost:3000/api/auth/google/callback
   http://localhost:3000/api/connections/google/callback
   ```

   - 1つ目: Google でログイン
   - 2つ目: Google ドライブ / スプレッドシート / Gmail / カレンダーの連携

6. 作成 → 表示された **クライアント ID** と **クライアント シークレット** を控える
   （シークレットは後から再表示できない場合があります）

> 本番環境では `http://localhost:3000` の部分を本番の URL（例: `https://app.example.com`）に置き換えたものを**追加**してください。開発用と本番用の両方を登録しておけます。

## 4. サービス連携で使う API を有効にする（ツール連携を使う場合）

ログインだけなら不要です。AI社員に Google のツールを使わせる場合は、「API とサービス」→「ライブラリ」で次を有効にします。

- Google Drive API
- Google Sheets API
- Gmail API
- Google Calendar API

## 5. `.env` に設定する

プロジェクト直下の `.env` に追加します（`.env` は Git にコミットされません）。

```bash
GOOGLE_CLIENT_ID="1234567890-xxxxxxxx.apps.googleusercontent.com"
GOOGLE_CLIENT_SECRET="GOCSPX-xxxxxxxxxxxxxxxx"
APP_URL="http://localhost:3000"
```

`APP_URL` は、手順 3 で登録した生成元と**完全に一致**させてください（末尾の `/` なし）。リダイレクト URI は `APP_URL` から自動で組み立てられます。

## 6. 設定を確認する

```bash
npm run google:check
```

- 登録すべき生成元・リダイレクト URI を表示します
- `.env` の値の形式をチェックします
- Google に問い合わせて、クライアント ID とシークレットが正しいかを確認します（アカウントやデータには何も変更を加えません）

`✓ Google がクライアント ID / シークレットを認識しました` と出れば OK です。

## 7. サーバーを再起動してログインする

```bash
npm run dev
```

<http://localhost:3000/login> に「Google でログイン」ボタンが有効になって表示されます。

- 初めてログインした場合は、そのまま会社作成（オンボーディング）に進みます
- 同じメールアドレスでパスワード登録済みの場合は、既存アカウントに Google ログインが紐づきます（Google 側でメール確認済みのアカウントのみ）

---

## FLUXA が要求する権限（スコープ）

必要最小限にしています。

| 用途 | スコープ | 分類 |
|---|---|---|
| ログイン | `openid` `email` `profile` | 通常 |
| Google ドライブ連携 | `drive.file`（FLUXA が作成・選択したファイルのみ） | 通常 |
| スプレッドシート連携 | `spreadsheets.readonly`（読み取りのみ） | 機密 |
| Gmail 連携 | `gmail.compose`（下書き作成・承認後の送信） | 制限付き |
| カレンダー連携 | `calendar.events` | 機密 |

- ログインはログイン用スコープしか要求しません。ドライブや Gmail への権限は、Connections で各サービスを接続したときに**サービスごとに個別に**要求します。
- 「テスト」状態のままなら、テストユーザー（最大 100 人）はすべてのスコープを審査なしで使えます。
- 一般公開（「アプリを公開」）する場合、**機密・制限付きスコープには Google の審査が必要**です。ログインだけ・ドライブだけを公開する場合は審査は不要または簡易です。

## 本番環境で公開するとき

1. `APP_URL` を本番の `https://` URL に設定
2. 手順 3 のクライアントに、本番用の生成元とリダイレクト URI を追加
3. OAuth 同意画面にプライバシーポリシー・利用規約の URL、承認済みドメインを登録
4. 「対象」→「アプリを公開」（テストユーザー以外もログインできるようになります）
5. Gmail / スプレッドシート / カレンダー連携を一般ユーザーに提供する場合は、Google の審査を申請

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| ボタンが「Google でログイン（未設定）」のまま | `.env` の値が空か形式違い。`npm run google:check` を実行し、サーバーを再起動 |
| Google の画面に `redirect_uri_mismatch` | 手順 3 のリダイレクト URI が `APP_URL` と一致していない（http/https、ポート番号、末尾の `/` を確認）。表示される URI をそのまま登録 |
| Google の画面に「アクセスをブロック: このアプリは…テスト中」 | ログインした Google アカウントがテストユーザーに登録されていない |
| ログイン画面に「Google ログインの設定に問題があります」 | クライアント ID かシークレットが間違っている。`npm run google:check` で確認 |
| 「ログインの有効期限が切れました」 | Google の画面で 10 分以上経過した、または別のタブで開いた。もう一度ログイン |
| 連携で「必要な権限が許可されませんでした」 | Google の同意画面で一部のチェックを外した。すべて許可して再接続 |
| 連携時に `access_not_configured` / 403 | 手順 4 の API が有効になっていない |
